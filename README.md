# AO2 - Tutorial on using Git, Github, and WebStorm

## Part 1: Directions on using these applications:

### 1. Create a Github Account
1. Click Sign up and make an account
2. Enter the information required
3. Complete the verification process
4. Sign in to your account

### 2. Download Git
1. Choose the correct download for your system and download Git
2. Open the installer
3. Download Git and follow all directions
4. Git will then track changes made to future projects

### 3. Download WebStorm
1. Go to the WebStorm link and download the application
2. Open the downloaded file and follow the directions
3. Open WebStorm after you installed

### 4. Create the Repository into WebStorm
1. Sign into your account
2. Click the + button
3. Select new repository
4. Enter the name as A02
5. Create a README file
6. Click Create Repository

### 5. Clone the Repository into WebStorm
1. Open the A02 Files on Github
2. Click the code button
3. Select HTTPS and put the repository URL
4. Open WebStorm
5. Click Get from VCS
6. Paste your GitHub repository URL and put it into the URL box
7. Select where you want to put the project to be saved into your computer
8. Click clone
9. Now you should see the A02 project in WebStorm

### 6. Edit the README file 
1. Find the README file in WebStorm
2. Open the file
3. Add the tutorial
4. Add the glossary
5. Add the references

### 7. Commit Changes
1. Open commit section in WebStorm
2. Select the files you changed
3. Enter a commit message to say what you changed
4. Click commit

### 8. Push your changes to GitHub
1. After you commit to the changes, select Push in Webstorm
2. Review the changes that are going to be shown
3. Click push
4. Open the A02 in Github
5. Check that the changes appear

### 9. Pull changes from GitHub
1. Open the project in WebStorm
2. Go to the Git menu
3. Click Pull
4. This will retrieve the changes from GitHub

### 10. Submit the Repository 
1. Open the A02 on GitHub
2. Copy the URL from browser
3. Submit the assignment on Canvas


## Part 2: Glossary

**Branch**- A separate version of the project where various changes could be made without changing the original version
**Clone**- A copy of the repository that is from GitHub that you can work on
**Commit**- A saved record of the changes you make on a project
**Fetch**- Downloads the changes you made from a remote repository without adding it to your current work
**GIT**- A version control system that tracks the changes made to files and keeps history of it
**GitHub**- A platform that used Git to store, manage, and share the repositories 
**Merge**- The process of combining changes from a branch into another
**Merge Conflict**- A problem that occurs when Git can't combine the changes because the same part of the file that is changed
**Push**- Sending commits from your computer to a repository like GitHub
**Pull**- Getting the latest changes from a repository and adding them to a local repository
**Remote**- A version of a repository that is stored somewhere else like GitHub
**Repository**- A project folder that has files in it and keeps track of the history of changes made in the files
